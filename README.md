## Возможности

- Создание разовой задачи.
- Создание серии задач по правилам повторения.
- Просмотр расписания с фильтрацией по датам.
- Обновление текста и статуса отдельной задачи.
- Удаление одной задачи или всей серии.
- Автоматическая генерация экземпляров задач по заданному расписанию.

## Работа с повторяющимися задачами

Для расчёта дат используется `rrule`.

При создании серии можно указать:

- дату начала;
- тип повторения;
- количество повторов;
- дату окончания серии.

### Обработка коротких месяцев

Если правило повторения задано на 29, 30 или 31 число, а в следующем месяце такой даты нет, задача переносится на последний день месяца.

Например, задача с датой 31 января будет создана 28 или 29 февраля, в зависимости от года.

### Шаблоны и экземпляры задач

Настройки повторения и сами задачи хранятся отдельно.

При создании серии сервис сохраняет шаблон с правилами повторения и сразу генерирует отдельные экземпляры задач на нужные даты. Благодаря этому врач может изменить статус, текст или дату одной конкретной задачи, не меняя остальные элементы серии.

### Хранение правил повторения

Конфигурация повторения хранится в `JSONB`.

У разных серий могут отличаться интервал, набор дней недели, дата окончания и количество повторов. `JSONB` позволяет хранить такие правила без добавления множества редко используемых полей в таблицу.

### Ограничение генерации

Для одной операции установлен лимит на число создаваемых задач. Это защищает базу данных от слишком больших серий, например ежедневных задач, созданных на много лет вперёд.

### Фильтрация расписания

Эндпоинт `GET /api/v1/tasks/` поддерживает параметры `from_date` и `to_date`. Это позволяет запрашивать расписание за конкретный период, а не загружать все задачи сразу.

### Удаление серий

При удалении шаблона связанные с ним невыполненные задачи удаляются вместе с серией. Отдельную задачу из серии можно удалить или изменить отдельно.

## API

### Создание и просмотр расписания

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `POST` | `/api/v1/tasks/` | Создать разовую задачу или серию задач через поле `recurrence`. |
| `GET` | `/api/v1/tasks/` | Получить расписание с фильтрацией по `from_date` и `to_date`. |
| `DELETE` | `/api/v1/tasks/templates/{template_id}` | Удалить шаблон серии и связанные невыполненные задачи. |

### Работа с отдельной задачей

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/v1/tasks/{task_id}` | Получить данные одной задачи. |
| `PUT` | `/api/v1/tasks/{task_id}` | Изменить текст или статус конкретной задачи. |
| `DELETE` | `/api/v1/tasks/{task_id}` | Удалить разовую задачу или один экземпляр из серии. |

## Настройка базы данных

Добавьте переменную `DATABASE_URL` в переменные окружения:

```bash
DATABASE_URL=postgresql+psycopg://user:pass@ip:port/db_name
```

Замените `user`, `pass`, `ip`, `port` и `db_name` на параметры своего подключения.

## Запуск

### 1. Поднять базу данных

Для локального запуска используется база данных из репозитория `medods/test-task-for-junior-backend-developer`.

```bash
git clone https://github.com/medods/test-task-for-junior-backend-developer
cd test-task-for-junior-backend-developer
docker compose up -d
```

### 2. Запустить сервис

Из директории проекта выполните:

```bash
docker-compose up --build
```

Контейнер приложения подключится к сети базы данных и применит миграции.

### Документация API

После запуска Swagger UI доступен по адресу:

[http://localhost:8000/docs](http://localhost:8000/docs)
